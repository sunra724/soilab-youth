# 리빙랩 공개 데이터 갱신 가이드

`/livinglab`의 문구, 현장의 질문, 리빙랩 과정, 회복을 살펴보는 영역, 실험 기록, 협력 유형과 FAQ는 `src/data/livinglab.ts`에서 관리합니다. 화면의 역할은 청년과 현장이 함께 질문을 찾고 시도하는 과정을 설명하는 것입니다.

## 2026-09-07 구성 정리

- 상단 메뉴명 `리빙랩`과 `/livinglab` 주소는 유지합니다.
- 페이지 순서: 리빙랩 소개 → 현장의 질문 → 함께하는 과정 → 회복의 변화 → 기록과 배움 → 지역 협력 역할 → FAQ → 연결·문의.
- 현장 질문의 `reading`에는 직접 관련된 연구노트를 연결합니다. 현재 8개 질문은 실험 제안이며, 별도 관찰 기록이 확인되지 않은 2개 항목도 가설로 표시했습니다.
- 회복 영역은 정해진 통과 순서나 평가 배점으로 표현하지 않습니다.
- KPI 대시보드와 도입 패키지는 페이지 본문에서 제외했습니다. 기존 데이터·필터·컴포넌트는 보존했으며 변경 자체가 수치를 승인하거나 패키지 정보를 다른 사이트에 자동 게시하지는 않습니다.
- 원문 근거는 `/research`, 센터의 성과는 `/#stats`, 기관의 정책·사업 검토는 `https://lab.soilabcoop.kr/stream`으로 연결합니다.
- 기존 `#outcomes` 링크는 근거·성과 연결 영역, `#packages` 링크는 기관 협력 문의 영역으로 이동할 수 있게 유지했습니다.

## 공개 전 원칙

- 내부 원자료를 공개 페이지나 저장소에 직접 연결하지 않습니다.
- 이름, 연락처, 상담기록, 진단명, 개인별 위험도, 세부 거주정보를 입력하지 않습니다.
- 소수집단을 추정할 수 있는 값은 숨기거나 상위 범주로 합칩니다. 기본 권장 기준은 `n < 5` 비공개입니다.
- KPI의 기간, 분자·분모, 정의, 중복 집계 기준, 출처와 갱신일을 함께 검토합니다.
- 실증사례는 개인 서사가 아닌 서비스 변화와 실험 학습 중심으로 작성합니다.

## 월 1회 갱신 절차

1. 사업담당자가 내부 원자료와 집계값을 대조합니다.
2. 지표의 기간·정의·분자·분모·중복 기준을 확인합니다.
3. 개인정보 담당자가 소수집단 추정 위험과 사례 공개 범위를 검토합니다.
4. 공개 승인된 항목만 데이터 파일에 반영합니다.
5. KPI는 `value`에 확정값을 입력하고 `status`를 `approved`로 바꿉니다.
6. 문제카드는 공개 승인 시 `status: 'approved'`, 실증사례는 `publicationStatus: 'approved'`로 바꿉니다.
7. `updatedAt`과 `source`를 실제 기준일·출처명으로 갱신합니다.
8. 아래 검증 명령을 실행한 뒤 배포합니다.

```bash
node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON --test tests/livinglab-data.test.mjs
npm run lint
npx tsc --noEmit
npm run build
```

## 상태별 공개 규칙

- KPI 데이터 필터: `status === 'approved' && value !== null`인 값만 공개용 목록에 포함합니다. `0`은 유효한 집계값입니다. 현재 리빙랩 화면에는 KPI 컴포넌트를 표시하지 않습니다.
- 문제은행: `status === 'approved'`인 항목만 표시합니다.
- 실증사례: `publicationStatus === 'approved'`인 항목만 표시합니다.
- 공개할 실험이 없으면 개별 기록이 아직 없음을 밝히고, 질문·방법·변화·다음 시도라는 기록 항목을 안내합니다. 제안 단계의 사례를 완료한 실험으로 표시하지 않습니다.
- 승인된 사업소개서 URL이 없으므로 소개서 버튼은 현재 표시하지 않습니다.

## 문의 경로

- 기관 리빙랩 협력 문의: 기존 대표 이메일 `soilabcoop@gmail.com`에 리빙랩 실증사업 문의 제목을 전달합니다.
- 청년·가족 지원 문의: `/research/support`의 지역 문의 안내로 연결합니다.
- 홈페이지에 기관용 문의 폼이 추가되면 `livingLabData.inquiry`와 페이지의 문의 링크를 갱신합니다.

## 변경 기록 권장 항목

변경일, 변경자 역할, 변경지표, 이전값, 변경값, 근거자료명, 승인자 역할을 내부 변경 기록에 남깁니다. 개인정보가 포함된 원자료나 담당자 실명은 공개 저장소에 올리지 않습니다.
