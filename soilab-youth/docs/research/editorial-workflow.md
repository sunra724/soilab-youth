# 정책·연구 발행과 갱신 절차

운영 기준 정리: 2026-09-07. 같은 원자료도 독자의 질문에 맞게 편집한다.

| 발행처 | 주 독자와 질문 | 발행물의 중심 |
| --- | --- | --- |
| 청년센터 정책·연구 | 청년·가족·지원 실무자: 어디에 문의하고 어떻게 지원할까? | 접수 경로, 당사자 선택, 가족지원, 회복 기록, 연구의 적용 한계 |
| 돌봄리빙랩 아카이브 | 돌봄 현장·연구자: 어떤 서비스를 설계하고 검증할까? | 돌봄 전달체계, 현장 실험, 서비스 설계, 평가 근거 |

한 원문을 모두에게 동일하게 재게시하지 않는다. 주 독자가 가장 잘 맞는 곳에 해설을 발행하고, 다른 사이트에는 그 독자의 질문에 맞춘 짧은 설명과 원문·해설 링크를 연결한다. 세 사이트 사이에 자동 발행 기능을 추가한 것은 아니다. 영업 포털의 구체적인 기준은 `C:\dev\soilab-portal\docs\stream-editorial-guide.md`를 함께 확인한다.

## 수집에서 자료 공개까지

1. `/research/review`에서 기존 검토용 키로 접속한다. 키는 문서·URL·화면 캡처에 적지 않는다.
2. 검토 대기 자료를 고르고 발행기관 원문을 연다. 제목, 저자, 발행일·조사연도, 연령, 지역, 표집, 법령 시행일을 확인한다.
3. 실제 읽은 범위를 `review_scope`에 적는다. 초록만 읽었다면 전문 검토라고 쓰지 않는다. 통계표에는 표 ID·기준연도·단위·분류·주석을 남긴다.
4. 자료 요약, 소이랩의 적용·검토 방향, 해석의 한계, 주제를 기록한다. 연구가 제안한 것과 효과를 검증한 것을 구분한다.
5. 미확인 사항이 남으면 대기로 저장한다. 근거를 확인하고 문안을 검토한 뒤 공개한다. 제외할 자료는 이유를 남긴다.
6. 공개 후 상세 페이지와 원문 링크를 확인한다. 오류가 있으면 대기로 되돌린 후 수정한다. 수집 원자료가 바뀌면 기존 수집기가 다시 검토 대기로 돌린다.

이 검토함은 수집한 정책·근거 자료를 관리한다. 연구노트, 지원 안내, 통계 원고는 아래 절차로 별도 배포한다. 자료를 승인했다고 연구노트가 자동 작성되거나 다른 사이트에 게시되는 것은 아니다.

## 연구노트

- `editorial-template.md`로 원고를 시작한다. 한 글에 하나의 현장 질문을 두고, 원문 근거와 운영 제안을 구분한다.
- 인용 쪽수는 인쇄 쪽수와 링크한 PDF 파일 순서를 함께 적는다. 장별 분할 PDF는 전체 PDF와 순서가 다르다.
- 발행기관, 연구대상, 조사방법과 한계를 대조한다. 부분 검토와 비공식 요약·번역 여부를 밝힌다.
- 확인된 원고를 `src/data/research-notes.ts`에 추가한다. 출처의 `evidenceId`가 실제 자료 페이지에 연결되는지 확인한다.
- `npm test`, 변경 파일 lint, `npm run build` 후 PC·모바일과 출처 링크를 확인한다. 배포 후 공개 URL도 확인한다.

## 지원 안내

- `/research/support`는 현재 확인된 대구 사업 문의처와 전국 사업의 지역 접수 확인 경로를 담는다.
- 주 1회와 새 공고 발견 시 모집 차수·기간·연령·거주지·가족 상담 조건·연락처를 확인하는 것을 운영 주기로 제안한다. 자동 확인 작업은 아직 등록하지 않았다.
- 지난 차수 신청서로 유도하지 않는다. 접수 중이라고 표시하려면 현재 공고의 기간·마감 상태를 확인한다. 전화 연결을 하지 않았다면 연결 확인이라고 기록하지 않는다.
- 전국 확대 발표만으로 대구 실제 접수 개시를 확정하지 않는다. `2026-09-07-policy-guide-draft.md`의 상세 법령 절차는 대구 접수기관·운영지침 확인이 남아 있다.

## KOSIS 통계 갱신

현재는 검토한 2025년 값의 정적 공개본이다. 매일 바뀌는 실시간 통계나 자동 발행이 아니다.

1. 앱 폴더에서 `node scripts/preview-research-kosis.mjs` 실행. 기존 `.env.local`의 KOSIS 키를 사용하며 결과는 `.local/research/kosis/`에만 저장한다.
2. `node scripts/prepare-research-statistics.mjs` 실행. 공개에 필요한 필드만 담은 `publication-candidate.json`을 만든다. 미제공 값을 0으로 채우지 않고, 예상과 다른 단위·분류·개수·기호는 재검토하도록 중단한다.
3. 원 통계표와 ITM·CMMT·PRD 메타데이터를 읽는다. 새 연도이면 `kosis-candidates.json`의 기간과 분류를 먼저 검토한다. 지역×연령 미제공, 연령 변화, RSE 표기, 모집단을 확인한다.
4. 후보 파일과 공개본을 비교하고 검토일 `checkedAt`을 입력한 뒤 `src/data/research-statistics.json`으로 복사한다. 확인일·기준연도에 맞춰 화면 설명과 사이트맵 수정일도 갱신한다.
5. 검사·빌드·배포 후 전국 연령대별 값과 대구 전체 연령 구분을 확인한다. KOSIS 조회 실패 시 기존 공개본을 유지한다.

사회조사 두 표는 격년, 사회통합실태조사 표는 연간 자료다. 새 공표 시 갱신하고, 월 1회 공표 여부를 점검하는 주기를 제안한다. KOSIS 비밀 키는 공개 JSON·저장소·클라이언트 코드에 들어가지 않는다.

## 아침 브리핑 점검

- 청년 브리핑: 오전 7시 예약 이후 `/research/briefings`의 날짜별 기록, 수집·전송 상태, 실제 텔레그램 채널 게시를 대조한다.
- 별도 NKIS Apps Script: 오전 7~8시 트리거가 실행된 후 실행 로그와 시트 전송 상태, 채널 게시를 확인한다. 테스트 성공과 예약 실행 성공을 구분한다.
- 2026-09-08 아침의 실제 실행 결과는 9월 7일 발행 작업에서 확인할 수 없다. 이번 작업은 미래 시간에 검사하는 별도 예약을 추가하지 않았다.

## 정정 기록

확인일, 수정한 문장·값, 수정 사유, 출처, 배포 URL을 날짜별 검토 문서에 남긴다. 실제 개인 상담기록이나 원문 PDF 전체를 공개 저장소에 추가하지 않는다.
