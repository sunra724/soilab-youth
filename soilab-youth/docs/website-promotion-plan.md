# 청년지원센터 웹사이트 홍보 운영안

작성일: 2026-09-07. 공개 중인 자료와 기존 소이랩 채널을 활용하는 첫 4주 운영 제안이다. 이 문서 작성으로 외부 게시·메일 발송·광고 집행이 실행되지는 않는다.

## 소개할 핵심

**고립·은둔 청년 지원에 필요한 문의 경로와 정책·연구 자료를 함께 살펴보는 소이랩 청년지원센터 웹사이트.**

지원 안내는 청년·가족에게, 정책·연구는 지원 실무자에게, 리빙랩은 협력기관에게 소개한다. 수행사례는 소이랩 영업 포털의 기존 자료를 활용한다. 대구 청년미래센터의 운영기관·개소·접수 여부가 확인되기 전에는 그 센터의 공식 홈페이지나 접수 창구로 소개하지 않는다.

| 순서 | 채널 | 실행할 내용 | 제안 주기 |

| 5 | 기존 협력기관의 담당자·소식지 | 담당 독자에게 맞는 소개문과 링크 제공. 기관의 게시 절차에 맞춰 자료실·소식지 게재 협의 | 첫 4주 중 소규모 시작 |

새로운 일일 홍보물을 만들기보다, 이미 검토한 연구노트·지원 안내를 한 주에 한 편씩 소개한다. 자동 수집된 자료를 사람의 검토가 끝난 연구 해설처럼 홍보하지 않는다.

>
> 소이랩 청년지원센터의 정책·연구 데스크에서 정책 원문, 연구노트, 지원 안내와 지난 브리핑을 함께 살펴볼 수 있습니다. 자료의 출처와 확인 범위, 현장에서 더 검토할 질문도 정리했습니다.
>

>
> 지원 안내: https://www.soilab-youth.kr/research/support

### 협력기관 대상 안내

> 소이랩은 고립·은둔 청년의 일상회복을 지원하기 위해 현장의 질문을 함께 검토하고, 지원 방법을 설계하는 리빙랩 협력을 제안합니다. 웹사이트에서 협력 과정과 정책·연구 자료를 살펴보실 수 있습니다. 수행사례는 소이랩 영업 포털의 기존 자료로 안내합니다.
>
> 리빙랩: https://www.soilab-youth.kr/livinglab

소개문은 게시할 채널의 목적에 맞게 하나를 선택한다. 청년·가족 대상 글에 영업 문의를 함께 강조하지 않는다.

## 첫 4주 실행 순서

| 시점 | 할 일 | 확인할 결과 |
| --- | --- | --- |
| 1주차 | 검색 등록 현황과 분석 도구 수집 상태 확인. 기존 채널 소개·고정 글, 사이트 간 연결 위치 정리 | 주요 주소와 공유 미리보기 정상, 게시 위치와 담당자 확정 |
| 2주차 | 가족의 첫 문의 연구노트 1편 소개. 기존 협력기관 중 관련성이 높은 곳에 안내 | 어떤 채널에서 어떤 글로 유입되는지 확인 |
| 3주차 | 발굴에서 첫 연결로 이어지는 연구노트 1편 소개. 질문·반응을 다음 해설 주제로 기록 | 안내 글의 유용성, 반복되는 질문 파악 |
| 4주차 | 일상회복을 어떻게 기록할지에 관한 연구노트 소개. 첫 4주의 이용 현황 검토 | 반응이 있는 독자·주제·채널에 다음 달 운영 집중 |

게시·연락 담당은 소이랩 운영자가 정하고, 웹 담당은 링크·검색·측정 설정을 맡는 구성을 제안한다. 외부 홍보의 실제 시작일은 담당자와 채널을 정한 뒤 기록한다.

## 검색과 유입 측정 준비

코드에서 확인된 기반은 `robots.txt`, 공개 자료를 포함하는 `sitemap.xml`, 페이지별 공유 정보, 기존 GA4 태그다. 검색 서비스 계정의 등록 상태와 GA4 보고서의 실제 수집·집계 상태는 이번 문서 작성으로 확인되지 않았다.

1. 네이버 서치어드바이저와 Google Search Console에서 `https://www.soilab-youth.kr`의 소유확인 상태를 확인한다. 사이트맵 주소는 `https://www.soilab-youth.kr/sitemap.xml`이다. 제출 뒤 대표 페이지의 수집·색인 상태를 확인한다. 사이트맵 제출만으로 검색 노출이 보장되지는 않는다. [네이버 안내](https://searchadvisor.naver.com/guide/request-feed), [Google 안내](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap?hl=ko)
2. GA4에서는 첫 주에 페이지 방문·유입 경로의 기준값을 확인한다. 구독·문의 버튼 클릭과 실제 구독·문의 완료는 서로 다른 지표이므로 구분한다. 전용 이벤트의 구현·집계는 별도 확인이 필요하다.
3. 채널별 캠페인을 비교할 때는 `utm_source`, `utm_medium`, `utm_campaign`을 일관되게 사용한다. 제안 이름은 `telegram / social / youth_desk`, `dasibom / email / youth_desk`, `partner / referral / youth_desk`이다. 이는 향후 사용할 규칙이며 현재 발송 링크에 적용된 상태가 아니다. [GA4 캠페인 URL 안내](https://support.google.com/analytics/answer/10917952?hl=en)
4. 현재 GA4 초기 설정의 `page_location`은 URL의 쿼리를 제외한다. 따라서 UTM을 붙였다는 이유만으로 채널별 캠페인 집계가 된다고 판단하지 않는다. 공개 홍보 파라미터만 허용하는 방식과 실제 수집 결과를 먼저 검증한다. 구독 확인·수신거부 토큰, 이메일, 상담 내용은 측정값에 포함하지 않는다.

첫 달은 확인되지 않은 방문자 목표치를 제시하기보다 방문·재방문·인기 자료의 기준값을 만든다. 구독과 문의는 집계 가능한 항목부터 건수만 기록한다. 이후 읽힌 자료, 유용했다는 반응, 실제 구독·협력 문의를 함께 보고 다음 달 목표를 정한다.
